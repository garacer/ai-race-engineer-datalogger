# 입력 형식

## 상태 JSONL

한 줄에 한 개의 JSON 객체를 저장합니다.

```json
{"age_seconds":0,"race":{"lap":2,"completed_laps":1,"sector":1,"last_lap_sec":120.0,"best_lap_sec":120.0}}
```

- `lap`: 1~10001 정수, `completed_laps`: 0~10000 정수, `sector`: 1~3 정수
- `last_lap_sec`, `best_lap_sec`: 20~900초 유한수 또는 아직 없는 경우 `null`
- `age_seconds`: 표본의 나이(초), 0~5초만 수용. 생략하면 로컬 재생에서 0으로 취급합니다. 실제 데이터 생산 시각을 검증하는 기능은 아닙니다.
- 최초 유효 상태는 기준선으로만 사용합니다. 중복, 세션 카운터 감소, 두 랩 이상의 누락에서는 완료 음성을 만들어 내지 않습니다.
- 잘못된 수치나 오래된 상태는 이벤트 없이 무시합니다. JSON 문법 오류는 CLI 오류로 반환됩니다.

## 이미 정렬된 CSV

| 열 | 단위/범위 | 의미 |
|---|---|---|
| lap | 문자열, 1~40자 | 비교할 랩 식별자 |
| distance_m | m, 0 이상 | 두 랩이 공유하는 같은 경로의 거리 좌표 |
| elapsed_s | 초, 0 이상 | 해당 랩의 경과시간 |
| speed_kmh | km/h, 0~350 | 관측 속도 |
| throttle_pct | %, 0~100 | 가속페달 입력 |
| steering_deg | 도, −720~720 | 조향 입력 |

각 랩 내부에서 거리와 경과시간은 엄격히 증가해야 합니다. 중복 거리·정지 구간을 가진 실제 로그는 먼저 별도로 정리해야 합니다. 입력을 자동 정렬하거나 누락을 채우지 않습니다. NaN·무한대·빈 수치는 거부합니다.

이 입력은 GPS 위경도를 포함하지 않으며 GPS 투영을 수행하지 않습니다. 다른 주행 라인에서 측정한 각각의 누적 이동거리를 자동으로 같은 좌표라고 볼 수 없습니다.

## 분석 기준 JSON

`sector_boundaries_m`는 공통 거리 범위 안의 증가하는 경계 목록입니다. `corners` 항목에는 고유한 `name`과 `center_m`가 필요합니다. 각 중심의 −70m~+80m 전체 범위가 두 랩 모두에 있어야 합니다. 배포 샘플의 코너와 섹터는 전부 가상입니다.

## 합성 데이터 출처

`tools/create_synthetic.py`는 가우스 함수로 두 랩의 속도·조향 패턴을 만들고 속도에서 경과시간을 적분합니다. 실주행 입력 파일을 읽지 않습니다. `data/synthetic`는 사람이 읽는 샘플, `jev/fixtures`는 설치 패키지용 동일 복사본입니다. 테스트에서 재생성 결과와 두 복사본의 동일성을 확인합니다.

상태 분류 시나리오의 5개 랩타임은 CSV의 두 합성 랩과 별개입니다. 두 입력을 같은 세션이라고 해석하지 마세요.
